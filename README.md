# Audio

Музыкальная веб-медиатека с синхронными текстами и редактором LRC → TTML. Интерфейс вдохновлён Apple Music; проект самостоятельный и не связан с Apple.

**[Открыть сайт](https://hellcat-audio-lyrics.gardentune257.chatgpt.site/)** · [Редактор текстов](docs/lyrics-editor.md)

## Возможности

- Личные аккаунты: почта и пароль, Google, GitHub. У каждого своя медиатека, избранное и плейлисты.
- Общий каталог: слушатели находят опубликованные песни и добавляют их к себе. Загружать и публиковать музыку может только администратор.
- Автоматическая группировка по артистам и альбомам, поиск, очередь, перемешивание, повтор, предыдущая и следующая песня.
- Обычный и большой плеер, мобильная версия, плавная пословная подсветка TTML и одновременные вокальные строки.
- Живой фон по палитре обложки с умеренной реакцией на сильные басы.
- Обложки из изображений, GIF и видео; отдельные аватары артистов, фото или видео в баннере, настройка положения и масштаба.
- Редактор для администратора: создание LRC из обычного текста, разметка слов пробелом, исправление времени в минутах и секундах, экспорт TTML и JSON.

Воспроизведение использует возможности браузера. Для неподдерживаемых им файлов предусмотрено преобразование через FFmpeg в WebAssembly; поддержка зависит от самого файла, кодека и ресурсов устройства. Защищённые DRM-файлы не поддерживаются.

## Локальный запуск

Нужен **Node.js 24** и npm.

```sh
npm ci
npm run dev
```

Открой адрес из консоли, обычно `http://127.0.0.1:5173`. На macOS также можно воспользоваться `Запустить.command`.

Локальная база SQLite и файлы создаются в `.local-data/`, отдельно от опубликованного сайта. В окне аккаунта только при разработке доступны тестовые входы «Админ», Alice и Bob. OAuth проверяется на опубликованном HTTPS-сайте с настроенными ключами; локальные тестовые входы не требуют настройки Google или GitHub.

```sh
npm test        # проверки таймингов, очереди, аккаунтов, доступа и OAuth
npm run build  # клиент и сервер в dist/
```

`npm run preview` показывает сборку клиента, но не запускает серверный API. Для проверки приложения целиком используй `npm run dev`.

## Как пользоваться

Администратор загружает аудио, при необходимости добавляет LRC/TTML и оформление. Новая песня сохраняется черновиком: для общего каталога выбери «Опубликовать на сайте» в меню песни. Слушатель открывает «Каталог музыки» и добавляет нужные треки в свою медиатеку.

Редактор открывается кнопкой «Редактор субтитров» внизу бокового меню. Подробности разметки и ограничения формата описаны в [инструкции редактора](docs/lyrics-editor.md).

Чтобы использовать GitHub для уже существующего аккаунта, сначала войди в Audio привычным способом и выбери **«Аккаунт → Подключить GitHub»**. Это сохраняет прежнюю медиатеку. Обычные аккаунты автоматически не объединяются только из-за одинаковой почты.

## Сервер и развёртывание

Клиент: JavaScript, CSS и Vite. Сервер: Worker ESM, база D1/SQLite, файловое хранилище R2. Основной опубликованный экземпляр размещён через Sites.

| Переменная сервера | Назначение |
| --- | --- |
| `PUBLIC_ORIGIN` | HTTPS-адрес сайта без завершающего `/` |
| `ADMIN_EMAIL` | Подтверждённая почта владельца; хранить как секрет |
| `GOOGLE_CLIENT_ID` | Идентификатор веб-приложения Google |
| `GOOGLE_CLIENT_SECRET` | Секрет Google; только на сервере |
| `GITHUB_CLIENT_ID` | Идентификатор OAuth-приложения GitHub |
| `GITHUB_CLIENT_SECRET` | Секрет GitHub; только на сервере |

Callback-адреса приложений:

```text
https://YOUR_DOMAIN/api/auth/google/callback
https://YOUR_DOMAIN/api/auth/github/callback
```

Google использует `openid email profile`, GitHub — только `user:email`. Оба входа защищены одноразовым `state` и PKCE; для Google дополнительно проверяются подпись ID token, издатель, получатель и `nonce`. Токены GitHub используются только для получения профиля и подтверждённой почты во время входа. Доступ к репозиториям для входа в Audio не нужен.

В Sites переменные задаются через защищённые настройки окружения. После изменения ключей нужна повторная публикация сохранённой версии. Манифест `.openai/hosting.json` содержит идентификатор существующего сайта: не используй его для создания независимой копии. При переносе настрой собственные D1/R2, переменные и адреса OAuth.

Схема базы — `db/schema.ts`, миграции — `drizzle/`. Новые миграции генерируются командой `npm run db:generate`; уже опубликованные миграции не меняй. Sites применяет их при развёртывании. Сборка Worker содержит защищённые файлы редактора: сервер проверяет права администратора перед выдачей.

Аудио — до 2 ГБ, оформление — до 256 МБ, тексты — до 5 МБ. Большие файлы передаются частями. Эти ограничения не отменяют квоты выбранного хостинга.

## Структура проекта

```text
src/                  плеер, медиатека, аккаунты, редактор и стили
server/               API, авторизация, загрузка файлов, локальный сервер
db/                   схема Drizzle
drizzle/              миграции SQLite/D1
scripts/              сборка и подготовка кодеков
tests/                автоматические проверки
docs/                 инструкции
privacy.html          описание использования данных
```

В репозиторий не входят пароли, OAuth-секреты, пользовательская музыка, личные базы и содержимое хранилища. Копия исходников не является резервной копией медиатек. Страница конфиденциальности независимой копии должна содержать сведения её настоящего владельца.

Черновики редактора сохраняются в браузере; для резервной копии экспортируй JSON. Восстановление пароля по письму пока не реализовано.

## Библиотеки и кодеки

Используются [Vite](https://vite.dev/), [music-metadata](https://github.com/Borewit/music-metadata), [jose](https://github.com/panva/jose), [Drizzle](https://orm.drizzle.team/) и [ffmpeg.wasm](https://github.com/ffmpegwasm/ffmpeg.wasm).

Кодеки восстанавливаются из зафиксированного npm-пакета при сборке и загружаются браузером по необходимости. FFmpeg Core распространяется по GPL-2.0-or-later; исходники и инструкции сборки находятся в [ffmpeg.wasm-core](https://github.com/ffmpegwasm/ffmpeg.wasm-core). У сторонних зависимостей собственные лицензии. Публикуй только музыку и оформление, на использование которых у тебя есть права.
